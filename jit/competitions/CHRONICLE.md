### Complete user-facing behavior
1. **Single viewport, mobile-first shell.** Fixed-height `100dvh` application, constrained desktop width (~850px), no parent-page scrolling. A separately scrolling workspace allows dense facts and checklists on a phone. Dark slate interface with warm-gold action accents, compact typography and responsive grid.
2. **Always-visible campaign header.** “COMPETITIONS”, JIT subtitle, active rank/name (01/QLOO, 02/PAYPAL, 03/NEBIUS), and a dated “RULES CHECKED 21 OCT 2026” label.
3. **Three portfolio metrics.** `$142.5k` combined advertised prize pools (`$25k + $67.5k + $50k`), `$47k` sum of first-place prizes (`$15k + $12k + $20k`), and days to earliest competition deadline. These are **aggregate opportunity figures**, not a claim of personally attainable winnings.
4. **Ranked competition selector.** Three persistent top tabs, QLOO/PAYPAL/NEBIUS. Each shows its first-place cash award and calculated days remaining; selecting a tab replaces the workspace with that competition's dossier without leaving the page.
5. **Evidence dossier per competition.** Competition title, rationale for rank, advertised total cash pool, first prize, exact deadline/timezone display, live countdown derived from the embedded deadline, registration snapshot (explicitly **not** completed submissions or win odds), estimated difficulty and engineering hours (explicitly **model estimates**).
6. **Sponsor requirements panel.** Embedded technical integration constraints, submission artifacts, judging summary, and a link to the official organizer rules. The page itself contains the operational summaries so the human need not browse sponsor sites for routine planning. Source attribution and verification date appear in the panel.
7. **Original project thesis and failure mode.** Each competition contains a tailored candidate build, an explanation of strategic fit, and the main risks. These are recommendations, not organizer facts.
8. **Prominent next move.** Each dossier has a contextual next-action callout and **COPY NEXT TURN** button. Qloo additionally exposes an **API ACCESS** link for the key-request dependency.
9. **Execution checklist.** Five concrete, competition-specific steps, each with a short clarification. A live `completed/5` count updates when checked. Progress is persisted locally in `localStorage` under `jit-competitions-checks`, keyed by competition and task index. Checkmarks are human-entered and **do not independently verify** Devpost registration, API access, source publication, or submission.
10. **Checklist reset.** RESET CHECKS clears only the selected competition's local checklist.
11. **COPY HANDOFF.** Exports structured `jit-competitions-handoff/v1` JSON with selected contest data, executing build fingerprint, verification snapshot date, and checked task names.
12. **Global 👁 export.** Copies `jit-competitions/v2` JSON with the build fingerprint, snapshot date, selected contest ID, all three complete contest dossiers and the local completion map. Copy feedback briefly changes the eye to ✓ (or ! on failure).
13. **Clipboard continuation.** COPY NEXT TURN copies a ready-to-send instruction naming the chosen contest, its next dependency, and the README/SPEC/CHRONICLE cold-boot reading contract. No direct model API calls or automatic conversation submission are implied.
14. **Executable build identity.** The footer initially says `calculating…`. An inline bootstrap defines `var BUILD = "pending"`, locates the main inline script by its `jit-competitions/v2` schema marker, computes SHA-256 over the executing script text via `crypto.subtle.digest`, and displays the first eight hexadecimal characters. If the publisher substitutes a non-pending value, that takes precedence. If hashing fails, the label reads `unverified`. This follows Ender Forge's runtime-content fingerprint convention and **is not the Git commit SHA**. The original Prize Orbit was observed in-browser with fingerprint `a893ac89`; the **new desk's browser fingerprint was not yet supplied**.
15. **Graceful local behavior.** Checklists load from `localStorage` if available; storage read/write errors are caught. Clipboard errors show ! rather than silently claiming success. Official links open externally only when explicitly selected.
